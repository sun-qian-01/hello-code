# SQL 基数估计实验报告

## 1. 任务理解

本实验的任务是根据简化 SQL 查询预测查询结果基数 `Cardinality`。输入字段包括查询涉及的表、连接条件和谓词条件；输出为测试集中每条查询的预测基数。评价指标为 Mean Q-Error：

```text
QError(y, y_hat) = max(y / y_hat, y_hat / y)
```

Q-Error 对高估和低估对称，且对小基数查询和极端偏差非常敏感。因此，本实验不直接优化均方误差，而是围绕对数基数、查询模板、谓词值分布和 OOF Q-Error 设计模型。最终提交文件为：

```text
submission_compliant_crossfit_blend_mean.csv
```

该方案只使用给定的 `train.csv`、`test.csv`、`column_min_max_vals.csv`、`schematext.sql` 及其派生特征，不使用测试答案或网上额外数据。

## 2. 数据处理

给定数据包括：

- `train.csv`：50,000 条训练查询，包含真实 `Cardinality`；
- `test.csv`：5,000 条测试查询；
- `sample_submission.csv`：提交格式；
- `column_min_max_vals.csv`：列最小值、最大值、表基数、不同值个数；
- `schematext.sql`：表结构说明。

查询结构呈星型模式：`title t` 为中心表，`cast_info ci`、`movie_companies mc`、`movie_info mi`、`movie_info_idx mi_idx`、`movie_keyword mk` 通过 `movie_id` 与 `title` 连接。

预处理步骤如下：

1. 将 `Tables` 解析为表组合，例如 `title t,movie_keyword mk`。
2. 将 `Join Conditions` 缺失值填为空字符串，并作为模板的一部分。
3. 将 `Predicates` 按三元组解析为 `(column, operator, value)`。
4. 构造 exact shape：`表组合 + 连接条件 + 谓词列与操作符序列`。
5. 使用 `column_min_max_vals.csv` 将谓词值归一化，并计算近似选择率。
6. 所有模型在 `log1p(Cardinality)` 空间训练和融合，最终再转换为正整数基数。

一个重要观察是测试集和训练集模板高度重合：测试集中 4,792 / 5,000 行的 exact shape 在训练集中出现过；`table + predicate columns` 层面几乎完全覆盖。因此，局部模板模型和专家路由比单一全局回归更适合该任务。

## 3. 特征设计

本实验使用三类特征和中间预测。

第一类是查询结构特征：

- 表组合；
- 连接条件；
- 谓词列序列；
- 谓词操作符序列；
- exact shape；
- `table + predicate columns` family。

这些特征用于划分局部专家和专家路由。

第二类是谓词数值特征。对每个谓词 `(column, op, value)`，根据 `column_min_max_vals.csv` 构造：

- 原始归一化值 `(value - min) / (max - min)`；
- 截断归一化值；
- `log1p(value)` 归一化值；
- 由操作符估计的选择率对数；
- 每条查询的谓词数量、选择率和、最小/最大选择率。

第三类是专家预测特征。最终 cross-fit blend 使用多个已通过 OOF 生成的 train-only 专家作为输入，包括：

- exact-shape residual surface 专家；
- value target encoding 专家；
- exact-shape KNN residual 专家；
- nested expert router 专家。

这些专家都以 `PredLog = log1p(predicted_cardinality)` 形式参与融合。

## 4. 模型与训练

最终方案由三层组成。

### 4.1 Exact-Shape Residual Surface

首先以 value target encoding 模型为底座，在 exact shape 内拟合残差曲面。对每个训练样本较多的 shape，使用归一化谓词值作为坐标，训练 Ridge / Huber 等低容量模型预测残差。再根据 OOF Q-Error 为每个 shape 选择是否采用该局部专家。

设计理由是：同一 SQL 模板内，谓词值变化通常对应较平滑的基数变化；按模板建模能减少全局模型在不同表组合之间的互相干扰。

### 4.2 Nested Expert Router

随后构造 `compliant_expert_router.py`。该脚本加载多个 train-only 专家，在外层 5 折中选择局部最优专家。路由层级包括：

- exact shape；
- `table + predicate columns` family；
- 表组合 family。

每个验证折的专家选择只使用该折训练部分的 Q-Error，不查看验证折标签，因此能降低直接按全量 OOF 选专家带来的泄漏风险。该阶段生成的主要候选为：

```text
submission_compliant_router_v2_knn.csv
```

其 OOF Mean Q-Error 为 `3.45484`。

### 4.3 Cross-Fitted Blend

最终模型使用 `compliant_crossfit_blend.py` 对强专家进行融合。融合输入包括：

- `compliant_router_v2_knn`
- `compliant_router_v2_weighted`
- `compliant_router_shape_mid`
- `shape_surface_v2_gate_g0p0`
- `shape_surface_v2_gate_g0p005`
- `shape_surface_v2_gate_g0p01`
- `shape_surface_v2_gate_g0p02`
- `shape_surface_m50_d2_a10_s0p3_g0p0`
- `value_te_capped_pair02_on_isotonic`
- `shape_knn_v2_m80_k50_t0p16_s0p15`

融合形式为专家 `PredLog` 的 softmax 加权平均，并附加一个接近恒等变换的仿射校准：

```text
pred_log = alpha * sum_i w_i * expert_i_log + beta
```

其中 `w_i` 由 softmax 保证非负且和为 1，`alpha` 限制在接近 1 的范围，`beta` 限制为小幅平移。优化目标直接使用训练折上的 Mean Q-Error。

为避免全量 OOF 调参过拟合，最终报告使用外层 5 折 cross-fit：

1. 每一折只在训练部分优化 blend 权重和仿射参数；
2. 用该折参数预测验证部分；
3. 拼接五折验证预测得到 leakage-checked OOF；
4. 最终测试提交再用全部训练集拟合融合参数。

## 6. 误差分析

从 OOF 结果看，最终 blend 相比单个 shape-surface 基线降低了平均 Q-Error，但中位数略有上升。这说明融合主要改善了尾部和部分高误差模板，而不是让所有样本的普通误差同时下降。

主要误差来源包括：

1. 高基数 ID 列的长尾分布。`ci.person_id`、`mc.company_id`、`mk.keyword_id` 等列存在强烈热度差异，仅凭训练集中出现的查询标签很难完全恢复真实频率。
2. 多表连接相关性。星型连接的真实基数取决于 `movie_id` 上的联合分布，单纯从列边际选择率无法准确估计。
3. 低基数查询的 Q-Error 放大。真实值很小的查询若预测偏大，会产生很高的 Q-Error。
4. OOF 与线上分布不完全一致。虽然测试 exact shape 覆盖率高，但具体谓词值、热门 ID 和模板频次仍可能与训练集不同。

因此，最终设计没有继续增加单个复杂模型，而是采用多个相对稳定专家的 cross-fitted 融合，用外层验证控制过拟合。

## 7. 复现说明

安装依赖：

```powershell
cd MachineLearning
Expand-Archive source_code.zip -DestinationPath source_code -Force
cd source_code
pip install -r requirements.txt
```

复现最终提交：

```powershell
python reproduce_compliant_crossfit_blend.py
```

`source_code.zip` 中包含源码、给定数据、基础专家 OOF/提交和必要中间产物。复现入口会按顺序检查或生成必要中间结果：

1. `shape_knn_residual_v2.py`
2. `compliant_expert_router.py`
3. `compliant_crossfit_blend.py`

如果中间 OOF 和提交文件已存在，复现脚本会直接校验最终文件；如需从头复现，可删除相关 `compliant_*`、`shape_knn_v2_*` 中间文件后重新运行。
